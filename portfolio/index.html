Case study

My EAAS — a university learning platform

The problem

Students needed one place for coursework, live classes and deadlines. Moodle has a mobile app, but it falls back to an embedded web view for most activity types — which is slow, unstyled and awkward on a phone.

My solution

A cross-platform app built directly on Moodle's web-service API, with native screens replacing the web views and a Supabase backend for everything Moodle doesn't do.

Key features

  • Native Moodle integration
  • Live classes (BigBlueButton)
  • Assignments & submissions
  • Attendance tracking
  • Push notifications
  • Calendar with local reminders

Tech stack

Impact. Shipped to both the App Store and Google Play. 9+ activity types moved off web views onto native screens, and an enforced Play API-level migration delivered a month before the deadline.

About me

More about me

I'm a developer working across the whole stack of an education provider's digital estate: the mobile apps students carry, the websites that bring them in, and the Moodle e-learning platforms everything talks to.

That range is deliberate. Because I administer the learning platform, I know exactly which web-service calls exist and how each feature really behaves — so the apps I build mirror the real workflow instead of guessing at it. And because I write the marketing pages too, the story a student reads before applying matches the product they get afterwards.

Three apps are live across the App Store and Google Play. Two institutional websites I built from an empty folder are serving real visitors. The rest is the unglamorous part — testing APIs, chasing store rejections, and fixing the live-class settings that stop a lecture starting on time.
