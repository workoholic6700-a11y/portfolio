Intro

I build things people log into every day.

I'm a developer working across the whole stack of an education provider's digital estate: the mobile apps students carry, the websites that bring them in, and the Moodle e-learning platforms that everything talks to — including course content, teacher accounts and the data behind them.

That range is deliberate. Because I administer the learning platform, I know exactly which web-service calls exist and how each feature really behaves — so the apps I build mirror the real workflow instead of guessing at it. And because I write the marketing pages too, the story a student reads before applying matches the product they get afterwards.

Three apps are live across the App Store and Google Play. Two institutional websites I built from an empty folder are serving real visitors. The rest is the unglamorous part — testing APIs, chasing store rejections, fixing the live-class settings that stop a lecture starting on time.

LIL
SPROUT

LilSprout

Final-year project Works offline

An offline learning app for young children, built as my BSc final-year project. The premise: children are going to be on a screen either way, so the useful question isn't how to take the phone away — it's how to make the time on it count. LilSprout borrows the shape of the games kids already choose, and puts learning inside it.

Everything runs with no internet connection, which matters in a country where a lot of households don't have reliable data — the learning shouldn't stop when the connection does.

  • Flutter
  • Offline-first
  • Local storage
  • Gamified learning
  • Early-years UX
